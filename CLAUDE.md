## Architecture (big picture)

A.D.A.M. is a multi-agent analysis copilot. **Today** it produces **educational** JSON (it is **not a broker** and executes no trades) consumed by the Next.js UI under `/analysis`. **Direction (ADR-005):** ADAM is evolving to *also* become a real trading-signal system — but under a hard discipline: **no signal is presented as tradeable until it clears the multi-regime / cost-aware / survivorship-corrected / pre-registered validation bar of ADR-004, and nothing currently clears it.** Rigorous backtesting (ADR-004) showed A3's price signals have **no robustly deployable edge — long or short — under honest scrutiny** (multi-régimen + costes + survivorship). The educational framing + disclaimers stay until the posture change is deliberate; the reusable validation gate is `scripts/multiregime-backtest.test.ts` (run with `RUN_BACKTEST=1`). Don't re-label the current signals as tradeable, and don't p-hack to "fill" the signal mode.

### The four agents + debate

Model assignment (ADR-001, referenced inline in `agents/a3/narrate.ts` and `agents/debate/prompt.ts`):

| Agent | Role | Model | Notes |
| --- | --- | --- | --- |
| A1 | Asset micro-snapshot | Haiku (narrate) | News + fundamentals + quote |
| A2 | Macro context | Sonnet | FRED-style series cached in `lib/a2-cache.ts` (Supabase Postgres `a2_cache` table, migration `0006_a2_cache.sql`; keyed on ticker + macro `as_of`; **no TTL** — invalidated organically when FRED rotates `as_of`, old row kept as inert history) |
| A3 | **Price action — isolated** | Haiku (narrate) + code (compute) | OHLCV only. See "A3 isolation" below. |
| Debate | Synthesis A1×A2 | Sonnet | Fires only if A1 or A2 flag a signal — downgraded from Opus to fit Hobby 60s lambda |
| A4 | System consolidator | Haiku (narrate) + code (confluence) | Final user-facing JSON; cites A3 verbatim |
| CMT scanner | Watchlist scan | **code (determinista, sin LLM)** | Reusa `computeTechnical()` vía `agents/cmt/build-signal.ts` (`buildCMTSignal`). Cron-driven vía `/api/cmt/scan` (`app/api/cmt/scan/route.ts`, schedule `0 21 * * *` en `vercel.json`; persiste a `signals_history`). Nota: `/api/cron/watchlist-scan` es un cron **aparte** (`30 21 * * *`) que pre-ejecuta el pipeline `runADAM` completo vía `runForUser`/`hasRecentAnalysis` (~5 LLM calls/ticker), **no** el CMT scanner. Señal siempre `1D`; intraday → MTF (no genera 1H). R/B mínimo por perfil forzado en código (default 1.5; ver `agents/a3/profiles.ts`). |

**If you change model assignment, update `MODELS` in `lib/anthropic.ts` AND the corresponding `narrate.ts` / `client.ts`. The costs and latency budget assume this allocation.**

### Pipeline shape — `runADAM()` is the primary path

`app/(workspace)/analysis/page.tsx` (via the client provider `components/analysis/run-provider.tsx:152`) hits **`/api/agents/run`** (the pipeline via `runADAM()` in `agents/pipeline.ts:170`). The legacy `/api/agents/a4` **orchestrator** and the `/api/agents/a1` per-agent endpoint were **removed** once `/run` became the live path (along with the `runA1`/`runA2`/`runA4` single-call clients). `/api/agents/a4` was later **re-created as a pure consolidator** (not an orchestrator): it takes already-computed `a1/a2/a3` (+ optional debate) and runs `computeConfluence` + `narrateA4` only — used to re-narrate A4 once the late A2 arrives (see "A2 caching pattern"). The remaining per-agent endpoints (`/api/agents/{a2,a3,debate,estructura}`) stay for cache-warming and ad-hoc calls (`estructura` is the opt-in 4th agent — see "Estructura agent" below). Note `/api/agents/a3` still uses the legacy `runA3` client + `agents/a3/prompt.ts` on purpose — that prompt carries the strong isolation blacklist (see "A3 isolation").

`runADAM()` orchestrates:

1. **Compute layer** (no LLM) — `agents/a3/compute/*` does deterministic TA: SMA/ATR/RSI/MACD (via `technicalindicators`) plus a **custom rolling VWAP** (`indicators.ts:75`), trend (HH/HL + monotonic fallback), levels (pivot clustering), patterns (double top/bottom, flags), operative (minimum R/B enforced in code — `MIN_RB_RATIO = 1.5` is the *default*; `agents/a3/profiles.ts` overrides per asset class: crypto 2.0, bond_etf 1.2). Since F8b the operativa `horizonte` is computed by **distance-to-target in ATRs** (`horizonteFromTarget` in `agents/a3/compute/operative.ts`: K = |target−entrada|/ATR, estBars = K² random-walk, estDays = estBars·intervalDays → <7d intradia / <30d swing / ≥30d posicional), with a `horizonteFallback` that never yields 'posicional' blindly (the old candle-span heuristic made everything 'posicional' with ~1y of candles in prod); the thresholds are deliberately aligned with the backtest windows — don't tune them without recalculating `HORIZON_WINDOW_DAYS` in `evaluate-trades`. EMA is implemented (`emaLast`) but **not surfaced** in the A3 output — `medias` exposes sma20/50/200 + vwap + golden/death cross (EMA is only used internally by MACD/cross detection). RSI+MACD surface in `A3Output.osciladores` (nullable/optional — confirmation, not driver). `agents/a4/compute.ts` computes confluence math: a **3-leg** (30/40/30 + alive-count capping) path AND a **4-leg** path (0.30/0.25/0.20/0.25 + `ALIVE_CAPS_4`) when Estructura is present, plus a signed `net_pct`/`kappa`/`actionable_pct` axes system (`schema_version` 2) persisted to `analyses_log` and consumed by the orbital hero.
2. **Narrate layer** (LLM) — each agent has a `narrate.ts` that turns compute output into narrative-only JSON validated against `A3NarrativeOnly` / `A4NarrativeOnly` in `agents/shared/types.ts`. The code merges back `ticker`, `confluence`, and the **literal `DISCLAIMER_LITERAL`** (U+00B7 separator — a single char drift fails Zod).
3. **Resilience** — `Promise.allSettled` on **A1/A3** only; A2 is resolved separately (cache read at `pipeline.ts:195`, or a `.then/.catch`-wrapped `narrateA2` awaited at 272-280). Any single agent failure degrades to partial. **All three failing** → `runADAM` throws `AllAgentsFailedError`, which `/api/agents/run` emits as a `fatal` NDJSON event `{ error:'all_agents_failed' }` inside the already-committed **HTTP 200** stream (route.ts:201-207). **A4 failure** → `narrateA4`'s error propagates out of `runADAM` (no try/catch, pipeline.ts:315) and is emitted as a `fatal` `pipeline_failed` NDJSON event in the same 200 stream (route.ts:208-214). The HTTP 503/500 paths (route.ts:232-250) only apply to **pre-stream** errors. Note: `A4FailedError` in the docstring (pipeline.ts:31) is never defined/thrown.
4. **Trace ID** — `runADAM` generates or accepts a `traceId` (UUID) and propagates it to every `narrate*` call. Used for log correlation and Sentry tags.

`runADAM` returns `{ output: A4Output, meta: { traceId, failures, debateRan, durationMs }, intermediates: { a1, a2, a3, debate } }`. The endpoint persists `intermediates.*` into `analyses_log` so reruns are auditable.

### A2 caching pattern — `skipA2Narrate`

`/api/agents/run` passes `skipA2Narrate: true` to `runADAM`. A2 is read from the **Supabase `a2_cache` table** only (via `readA2Cache` in `lib/a2-cache.ts`, which uses `createSupabaseAdmin().from('a2_cache')`); on cache miss with `skipA2Narrate: true` A2 stays `null` and the pipeline degrades gracefully. (**Upstash is used only for rate limiting** in `lib/ratelimit.ts`, not for this cache.) The frontend fires `/api/agents/a2` in **parallel** from the `RunProvider` (`components/analysis/run-provider.tsx`, `a2Promise` at line 160) to warm the cache in its own lambda — splitting load away from the 60s budget of `/run`; `app/(workspace)/analysis/page.tsx` only consumes run state via `useRun()` and contains no fetch calls. Tests and legacy callers that omit `skipA2Narrate` get the inline narrate behaviour. If you add a new caller, decide consciously which mode applies.

**First-run A2 gap + re-narrate.** On a ticker's first analysis the A2 cache is cold, so `/run` returns `a2: null` and A4 is baked with "A2 unavailable" + degraded confluence. When the parallel `/api/agents/a2` resolves, the frontend updates the A2 card (the confluence indicator recomputes client-side via `lib/confluence`) **and** calls the `/api/agents/a4` consolidator to re-narrate A4 with the now-complete `a1/a2/a3` (best-effort — on failure the prior A4 stays). When the frontend passes `analysisId` to the consolidator, it **also** updates the already-persisted `analyses_log` row via `consolidateAndPersistA4` (`app/api/agents/a4/route.ts` → `agents/a4/consolidate.ts`), so the stored A4 reflects the complete a1/a2/a3 — the first-run gap is closed in persistence too. **Server-side**, the `a2-reconcile` cron (daily) also pre-warms `a2_cache` and backfills null-A2 `analyses_log` rows (only rows **< 72h**, before the 7d `signal_outcomes` horizon so already-measured calibration isn't corrupted) via `consolidateAndPersistA4`, and deliberately preserves any existing `estructura_output` leg.

### Estructura agent (futuros · MTF)

A deterministic **4th agent** not covered by the four-agent table above. It has compute + narrate + endpoint (`POST /api/agents/estructura`) + its own page (`app/estructura/page.tsx`) + a futures symbol resolver (`agents/estructura/symbols.ts`, e.g. `resolveEstructuraSymbol('XAUUSD') → 'GC=F'`). It runs **opt-in, outside `runADAM`**: `components/analysis/run-provider.tsx` fetches `/api/agents/estructura` in parallel and feeds it to `app/api/agents/a4/route.ts`'s `consolidateAndPersistA4`, which persists a dedicated `estructura_output` column in `analyses_log`. It has its **own isolation invariant** — a `CLAVES_PERMITIDAS` runtime guard in *both* `agents/estructura/compute.ts` and `agents/estructura/narrate.ts`, plus a `.strict()` Zod schema at the route — a mirror of A3 isolation, with its own tests. Treat it as protected like A3 (see "What not to touch").

### Market data — Yahoo + Finnhub + FRED (macro) + crypto providers

`lib/market/finnhub.ts` exposes `fallbackQuote / fallbackDaily / fallbackIntraday / fallbackOverview / fallbackNewsSentiment`. Yahoo serves prices and candles (no auth, realtime); Finnhub serves fundamentals and news. `lib/market/macro.ts` adds a daily-cached macro snapshot used to populate `MarketSnapshot.macro_snapshot`. **Alpha Vantage was removed** — do not reintroduce it.

**Crypto (A1) — Finnhub doesn't cover crypto, so A1 has dedicated providers.** `lib/market/crypto-registry.ts` is the single source of the 13-coin set + per-provider ids (`isCryptoTicker` / `cryptoMeta`); it replaced the old double-role of `coingeckoId` as the crypto detector. Fundamentals come from a resilient chain in `lib/market/crypto-fundamentals.ts`: **CoinMarketCap** primary (`coinmarketcap.ts`, numeric id, header `X-CMC_PRO_API_KEY`) ∥ **CoinGecko** in parallel (`coingecko.ts` — supplies ATH, which CMC/CoinStats don't, plus backup) → **CoinStats** last resort (`coinstats.ts`, header `X-API-KEY`). News come from **newsdata.io** (`newsdata.ts`, `/crypto?coin=`), merged into `snapshot.news`. `snapshot.ts` only calls these when `isCryptoTicker(ticker)`. Keys: `CMC_API_KEY` · `COINSTATS_API_KEY` · `NEWSDATA_API_KEY` (+ optional `COINGECKO_API_KEY` for a higher rate limit); each degrades independently (no key → that provider is skipped, chain falls through). `isCryptoTicker` is also imported by the UI (A1 card / `app/(workspace)/analysis/page.tsx`) to label data sources correctly for crypto vs equity.

Every market call is wrapped in `.catch(() => null|[])`. The fan-out + null-quote recovery (last-vela fallback) + `MarketSnapshot` assembly live in **`lib/market/snapshot.ts` (`buildMarketSnapshot`)**, shared by `app/api/agents/run/route.ts` and the cron's `lib/pipeline-runner.ts`.

Four self-contained read subsystems with their own `lib/` trees — don't duplicate their logic:

The signals UI lives in the shared lib `components/signals/*` (helpers/outcome/primitives/signal-card/track-record), consumed only by `components/watchlist/radar-actionbar.tsx` (per-**ticker** urgency counters — not per-signal like the old page; track-record via its own `GET /api/signals` fetch; "Buscar señales" = whole-watchlist scan by default, explicit max-5 selection folded as advanced mode) and `radar-signal-panel.tsx` (collapsible actionable levels + optimistic ack). The endpoint attaches each row's backtest outcome via a **second best-effort query** on service-role-only `signal_trade_outcomes`, bounded by `.in('signal_id', ids)` where the ids come exclusively from RLS-filtered RPC rows — an anti-cross-user-leak pattern locked by `app/api/watchlist/radar/__tests__/route.test.ts`; enrich the radar by adding endpoint queries, never by widening the RPC or unbounding that query. Levels travel in `RadarSignal_t`, mapped defensively in `lib/radar/normalize-signal.ts` (missing/miscast → null, the signal is NOT dropped; `outcome` is always null there — only the endpoint fills it); indicators deliberately do NOT travel in the radar contract (only in `GET /api/signals`).
- **Analyses derivation** — `lib/analyses/*`, the SSOT pair for everything derived from persisted jsonb: `trade-summary.ts` (`extractTradeSummary` / `extractEstructuraTradeSummary` — the canonical "does this analysis have an actionable trade". Callers of the *functions*: `GET /api/analyses`, `app/historial/page.tsx`, and — the Estructura variant only — the `evaluate-trades` cron; `/api/analyses/[id]` and `stored-analysis-view.tsx` import only the module's *types* and receive already-extracted trades. Caveat: the cron's A3-side `extractPlan` is a local reimplementation that skips the `buildSignalTradePlan` geometry check `extractTradeSummary` performs — don't add a third variant. In `trade-summary.ts` geometry is validated by delegating to `buildSignalTradePlan`, which only REJECTS degenerate/inverted geometry — direction always comes from the agent's signal) and `horizon.ts` (`horizonteLabel()` — the ONLY enum→label layer for `TradingHorizon`, the UI never prints the raw enum; `horizonteFromEstructuraTimeframe` maps 1H/4H→intradia, 1D→swing, 1W→posicional). ### Auth, rate limits, CSRF

- Supabase auth via `lib/supabase/{server,admin,browser,middleware}.ts`. Cookie-based.
- `lib/ratelimit.ts` — **lazy-init Upstash limiters**. Without `UPSTASH_REDIS_REST_*`, dev uses a NOOP limiter; prod throws on first `.limit()` (fail-closed by design). The lazy getter pattern exists because eager init at import time poisoned `middleware.ts` and 500'd every route.
- `lib/api-helpers.ts` — `checkSameOrigin` (CSRF) and `rateLimitByIP` (must be called from Node-runtime routes, not Edge — `@upstash/redis` is not Edge-compatible).
- `/api/agents/run` enforces: CSRF → IP rate-limit (5/min + 30/day) → auth → per-user limit (30/day).
- **`/system` console** has its own authorization layer (distinct from the cookie auth above): allowlist-gated by table `system_access` via the SECURITY DEFINER RPC `is_system_authorized()`, wrapped by `lib/auth/system-access.ts` (`requireSystemApi`). Invariants: **default-deny on any error** (never fail-open) and **no caching** (revocation is immediate). Internal `/api/system/*` + `/api/metrics/calibration` must call `requireSystemApi()`.

### Timeout and retry policy

Defined in `lib/anthropic.ts`:

- **`DEFAULT_TIMEOUT_MS = 25_000`** per LLM call. Callers can override via `timeoutMs`, but **don't naïvely raise this above 30s for pipeline calls** — there is a documented 504 incident from raising it to 30s without recalculating worst-case (5s data + 30s parallel A1/A2/A3 + 30s debate + 30s A4 = 95s, well over the Hobby 60s lambda). The current `25s + Debate ~12s + A4 ~12s = ~54s` budget fits with a cushion.
- **`MAX_ATTEMPTS = 2`** parse/schema retry inside `runWithParseRetry()`. JSON-malformed or schema-mismatch outputs are retried once; network/5xx errors are NOT retried here (the SDK already handles those). Both intermediate failures log WARN; the final fail logs ERROR + throws `AgentParseError`.
- **`maxRetries: 1`** on the SDK client itself. Bumping this multiplies worst-case latency through every call site.

### Observability (Sentry)

`instrumentation.ts` initializes Sentry server/edge. `/api/agents/run` captures **per-agent failure as `level: 'warning'`** (not error) with tags `{agent, ticker, traceId}` — the pipeline degrades gracefully, but without these captures a chronic A2 timeout was invisible in diagnostics. Top-level handler captures pipeline failures with `level: 'error'`.

### Cron jobs

`vercel.json` wires **six** crons. Every one is guarded by `if (auth !== \`Bearer ${CRON_SECRET}\`) → 401` (Vercel injects that header only when `CRON_SECRET` is set) and runs under `createSupabaseAdmin` (service-role, **RLS-bypass**), some with `maxDuration` up to 300s. When adding a cron, keep the Bearer guard and mind ordering dependencies (e.g. `evaluate-signal-trades` runs after `evaluate-trades`).

| Cron | Schedule | Does |
| --- | --- | --- |
| `cron/a2-reconcile` | daily | pre-warm `a2_cache` + backfill null-A2 rows via `consolidateAndPersistA4` (maxDuration 300s) |
| `cron/watchlist-scan` | `30 21 * * *` | pre-runs full `runADAM` into `analyses_log` (maxDuration 300s) |
| `cmt/scan` | `0 21 * * *` | CMT `buildCMTSignal` → `signals_history` |
| `cron/evaluate-signals` | daily | directional 7d/30d hit scoring → `signal_outcomes` |
| `cron/evaluate-trades` | daily | path-dependent stop/target de **dos fuentes** por análisis — operativa A3 (`source='a3'`) y plan de Estructura (`source='estructura'`, `setup.estado ∈ {listo, esperando_confirmacion}`) → `trade_outcomes`, una fila por `(analysis_id, source)` |
| `cron/evaluate-signal-trades` | daily | path-dependent of CMT signals → `signal_trade_outcomes` |

### Backtesting / outcome evaluation

The three `evaluate-*` crons (above) score matured analyses/signals into `signal_outcomes` / `trade_outcomes` / `signal_trade_outcomes` via **pure evaluators** (`lib/backtest/trade-eval.ts`, `lib/backtest/signal-plan.ts`, `lib/scoring.ts` — volatility-adjusted threshold `max(2%, ATR_K·ATR%)`). Load-bearing invariants: **forward-looking candle windows only** (no look-ahead bias), **idempotency** via 23505-conflict tolerance — for `trade_outcomes` the conflict key is the **composite PK `(analysis_id, source)`** since migration `0018_trade_outcomes_source.sql` (`source ∈ {'a3','estructura'}` is a CHECK column, **not** a Postgres enum: it does not appear in the generated `Database['public']['Enums']`; the TS union `TradeSource` is hand-written in `lib/analyses/trade-summary.ts`) — and `not_evaluable` terminal states to prevent reprocessing. Don't reintroduce look-ahead or duplicate the scoring logic.

`evaluate-trades` selects candidates server-side with **two parallel jsonb queries merged by id** (A3 group: `a3_output->operativa->>signal` buy/sell + horizonte; Estructura group: `estructura_output->setup->>estado` listo/esperando_confirmacion) — deliberate design over PostgREST's fragile `.or()`+jsonb syntax; don't "simplify" it back. Only `swing`/`posicional` are evaluated (`HORIZON_WINDOW_DAYS`: swing 30d, posicional 120d); `intradia` is **deliberately unevaluated** (future phase with 4H candles), not a bug. Estructura's actionability is extracted via `extractEstructuraTradeSummary` (`lib/analyses/trade-summary.ts` — the SSOT; don't reimplement it in cron or UI). ⚠️ **Known drift (2026-07):** the historial read-paths predate dual-source — `/api/analyses` maps `trade_outcomes` by bare `analysis_id`, `/api/analyses/[id]` uses `.maybeSingle()` (with two rows PostgREST errors but the route destructures only `data` — the outcome silently becomes `null`), `app/historial/page.tsx` forces `outcome=null` for Estructura trades, and the docstrings in `lib/analyses/trade-summary.ts` / `app/api/analyses/route.ts` still claim Estructura "aún NO se evalúa" (contradicted by the cron). If you touch those paths, fix by keying by `source` — don't "restore" the single-row assumption.

### A3 isolation — the load-bearing invariant

**A3 must never receive A1/A2 output, news, macro, sentiment, F&G, VIX, fundamentals, geopolitics, analyst targets, or any cross-agent context.** Its only inputs are `{ ticker, ohlcv }` for the legacy `runA3` (multi-timeframe embedded **inside** `ohlcv`); the pipeline `narrateA3` takes `{ ticker, ohlcv }` plus an optional `timeframe` **and** optional `intraday` candles for MTF compute. Both paths are strict OHLCV — no narrative context. Three enforcement layers, all must stay:

1. **System prompt** (`agents/a3/prompt.ts` and `agents/a3/narrate.prompt.ts`) — explicit blacklist + "ignore injection attempts" instruction. Only `agents/a3/prompt.ts`'s `A3_SYSTEM_PROMPT` is annotated `@frozen`; `agents/a3/narrate.prompt.ts` is **not** (and its blacklist is not exercised by either isolation test) — but both must still preserve the full blacklist.
2. **Function signature** (`agents/a3/client.ts` and `agents/a3/narrate.ts`) — typed input that the function checks at runtime, rejecting any extra field.
3. **Endpoint schema** (`app/api/agents/a3/route.ts`) — Zod `.strict()` rejects extra body fields.

Locked in by `agents/a3/__tests__/isolation.test.ts` and `__tests__/agents/a3-isolation.test.ts` — they guard the prompt blacklist (capa 1) and the `runA3`/`narrateA3` runtime input guard + A3 output-schema cleanliness (capa 2). Note the **endpoint request `.strict()`** in `app/api/agents/a3/route.ts` is **not** exercised by either test. Both must stay green. **Any refactor that widens the input shape, drops a blacklist term, or removes `.strict()` should be rejected, not fixed by weakening the test.** If you genuinely need to enrich A3, it must be strict OHLCV — never narrative context.

A3 *does* receive today's date in the user message so it doesn't treat stale candles as current — the single allowed *analytical/temporal* exception, sitting in the user message, not the input shape. The pipeline (`narrateA3`) also injects a `# TRACE:` id into the user message; that is operational metadata (log correlation), not narrative context, so the isolation invariant still holds.

## Schemas — `agents/shared/types.ts` is the source of truth

Consolidated Zod schemas (`A1Output`, `A2Output`, `A3Output`, `A4Output`, `DebateOutput`, `CMTOutput`, `ConfluenceResult`, narrative-only variants, shared enums) live in `agents/shared/types.ts` and use `.strict()` — **single source of truth; import schemas/types from here**. (Sole exception: `A4NarrativeOnly` is intentionally **non-strict** — see the comment at `agents/shared/types.ts` l.205-209 — so extra fields from lenient models like Haiku are stripped rather than rejected.) The legacy numbered `agents/a{1,2,4}/schema.ts` were **removed**; among the a1-a4 pipeline agents only `agents/a3/schema.ts` survives (still consumed by the legacy `runA3` client + A3 isolation tests). **A3's two schemas can silently diverge** (F8a lesson): `operativa` inside `agents/a3/schema.ts` is a non-strict `z.object` (strip mode), so a field that exists in compute / `shared/types.ts` but is missing there gets silently dropped on the legacy path — no Zod error, no red test (exactly what happened to `entry_type` pre-F8a). Add any new operativa field to **both** schemas, and keep it nullable+optional in `a3/schema.ts` (the `@frozen` legacy prompt doesn't ask the LLM for it). Note that **non-pipeline agents keep their own schema files** that are NOT consolidated into `shared/types.ts` and can diverge: `agents/debate/schema.ts` (non-strict), `agents/cmt/schema.ts` (indicators cap 6 + non-strict vs shared `CMTOutput`'s cap 5 + strict), and `agents/estructura/schema.ts` (`EstructuraOutput` not in `shared/types.ts` at all). The `DISCLAIMER_LITERAL` constant uses U+00B7 — match it exactly or the schema rejects it.

**Supabase DB types are generated, not hand-written.** `types/db/supabase.ts` is the `supabase gen types` output (the source of truth for `createClient<Database>`); `types/db/index.ts` re-exports `Database` + derives domain aliases (`Watchlist`, `AnalysisLog`, …) from it. **Application source** (`agents`/`app`/`components`/`lib`/`hooks`/`types`, excluding tests) is **zero `as any`/`as unknown`** — do not reintroduce casts on Supabase calls. (There is no literal `src/` directory, and `scripts/*.ts` still contain a few isolated casts, e.g. `scripts/experiment-fase1b.ts` and `scripts/calibrate-confluence-axes.ts`.) After a migration, regenerate: `supabase gen types typescript --project-id qaakauberbibfgxthlro > types/db/supabase.ts`, and keep `@supabase/ssr` aligned with `@supabase/supabase-js` (its peer). For jsonb payloads use `type` (not `interface`) so they're assignable to `Json`. The full migration workflow (SQL → apply → regenerate → header/alias wiring → typecheck) is packaged as the project skill **`.claude/skills/supabase-migration`** — if you change any migration convention, update the skill too or they diverge.

## Dev-time gotchas

- **`.env.local` is read at process start.** Editing it while `next dev` is running has no effect on `process.env` until restart. `assertApiKey()` in `lib/anthropic.ts` throws at the first `runAgent` call if `ANTHROPIC_API_KEY` is missing — fail-loud by design, but invisible until the first request lands.
- **Don't redirect native exe stderr through PowerShell pipelines on Windows 5.1** — it wraps stderr in `NativeCommandError` records and sets `$?` to false even for successful exits. Run npm/pnpm from `cmd.exe //c "..."` if PowerShell execution policy blocks `npm.ps1`.
- **Hobby plan lambda timeout is 60s.** Treat this as the hard ceiling whenever you touch `DEFAULT_TIMEOUT_MS`, `MAX_ATTEMPTS`, or add new sequential LLM calls to the pipeline. A 504 in prod means you broke the worst-case math.
- The repo has worktrees under `.claude/worktrees/` (agent isolation mode). Their `CLAUDE.md`/code may diverge from main — they're disposable.

## Design system invariants

The UI design system is real and load-bearing — verified facts, not aspirations (audited 2026-06-22). Extended docs: `docs/handoff/` (descriptive, per screen) + `docs/adr/` (prescriptive ADRs; `0002-a3-operativa-trade-plans.md`, `0003-radar-unificado-y-temporalidad.md` — the latter's "Invariantes (no romper)" is binding for radar/horizonte work; **`0004-a3-edge-corto-lado-largo-no-validado.md`** — the multi-régimen/costes/survivorship finding + binding invariants (**keep `A3_LONG_TREND_FOLLOW` OFF**; don't wire `agents/a3/compute/exhaustion.ts` as a live signal; don't p-hack on the same sample; don't call the long "refuted"); **`0005-adam-hacia-senales-reales.md`** — the strategic pivot to a real signal system and its admission bar; ADR-001 inline in code comments).

- **Token SSOT = `tailwind.config.ts`** (`theme.extend.colors`), mirrored EXACTLY in `app/globals.css :root` (void/surfaces/borders/accent). Keep them in sync — a divergence is what produced the old "azulado vs neutro" drift. There are **zero `bg-[#…]` hardcodes** in `app`/`components`; don't introduce any.
- **Semantic market color is intocable:** `emerald` (alza/bullish), `rose` (baja/bearish), `amber` (atención/pendiente) — **only** on data, levels, direction and signal-state. **Never** on chrome, nav, identity badges or decoration.
- **`accent #5B8AF0` = brand** (input focus, links, active tab/state, wordmark): moderate use, never decorative fill. The identity is **neutral-premium + accent ("Instrumento de precisión"), NOT monochrome B&W** — that reskin is superseded (see this "Design system invariants" section / the token SSOT; no ADR documents the supersession).
- **Text hierarchy by opacity over `ink #F5F5F7`** (`ink/66` secondary, `ink/45` metadata). Text uses `text-ink/X` (the SSOT) everywhere — the old `text-white/X` debt was migrated wholesale (2026-06-29). Don't reintroduce `text-white` for text; `border-white/X` and `bg-white/[0.0X]` overlays stay (the border/overlay token is white-alpha by design).
- **Wordmark "A.D.A.M." = Inter `font-extrabold` + wide tracking** (Orbitron retired 2026-06-22). Don't reintroduce display fonts.
- **A3-isolation applies to the UI too:** the A3 card and the Estructura card never render cross-agent narrative context (news/macro/sentiment) — only what their isolated compute produces. Don't "enrich" them with A1/A2/macro data.
- **Progressive disclosure in agent cards (2026-07):** 3-level model — level 1 = the shell's verdict row, level 2 = decision-grade essentials, level 3 folded under the shared primitive `components/disclosure.tsx` (`<Razonamiento>`: real `<button aria-expanded>`, chrome-only affordance (ink/accent, never market color), reveal via the **existing** `fade-slide-in` token under `motion-safe:`, chevron mirroring the shell's `›`). Reuse it for any new in-card disclosure — don't hand-roll toggles. Consumers: a1/a2/a3/debate cards (a4 and estructura don't use it). In A3's signal headline only the **direction** carries market color; `confianza NN%` is chrome (`text-ink/70`) — a deliberate firewall application, don't "recolor" it back. `<Razonamiento>` also takes `landNonce` (one-shot accent underline via `animate-reasoning-land`, `motion-reduce:hidden`), driven by the same landing beat as the shell's `land-flash` — see the vitality bullet.
- **Vitality is hero-led (Fase 1, 2026-07):** during a run the cards stay calm — the per-card `animate-sweep` chrome was **retired**; card status lives in the StatusDot plus the shell's one-shot `land-flash`. Ambient liveness belongs to the OrbitalHero and the sticky `components/analysis/running-bar.tsx` (mutually exclusive with the VerdictBar in the `sticky top-0` slot; rendered only while `a4Status` isn't done/error). RunningBar invariants: it NEVER shows the asymptotic number (the hero is the only indeterminate clock), its per-agent dots light on `settled` (done/anomaly) like the satellites, chrome is accent/ink only. The landing beat has a **single source**: `hooks/use-landing-beat.ts` — a nonce that bumps only on the real `scanning→landed` edge and does NOT fire when mounting an already-landed persisted run (honesty). Don't add a second landing animation or hand-roll the edge detection. `lib/motion.ts` is the **wired SSOT** for the shared tempos: `tailwind.config.ts` imports `VITALITY`+`EASE_PRECISE` to build the `precise` timing-function and the `land-flash`/`reasoning-land` animations (`VITALITY.agentLandingMs` = 420ms), and `orbital-hero.tsx` reads `VITALITY.resolveCrescendoMs` (520ms) for the crescendo pop — change a shared tempo in ONE place. `lib/motion` is dependency-free precisely so the build config can import it — keep it that way (a client-only import there would break `next build`). (`RUN_TIMING_ESTIMATE` stays explicitly unmeasured until real capture.) `lib/run/timing.ts` is dev-only stream instrumentation (console.table in dev only; must never print or mutate state in prod), there to calibrate `lib/motion.ts` with real data.
- **/inicio decorative layers are dependency-free canvas 2D** (`components/inicio/decor/constellation.tsx`, `components/inicio/scrolly-story.tsx`): no framer-motion (nine *other* inicio files do use it, always gated with `useReducedMotion`/`useInView`; **`AnimatePresence` remains at 0 uses repo-wide** — no precedent), DPR≤2, IntersectionObserver + `document.hidden` gating, and a pinch-zoom-proof resize guard (rebuild only if the real canvas size changed ≥2px, debounced — iOS fires resize on zoom; removing it reintroduces already-fixed mobile bugs). Reduced-motion/no-JS degrade to *nothing*: ScrollyStory returns `null` (all real content lives in the sections below it; keep the `#como` skip-link target in `how-it-works.tsx`), Constellation emits no events and the header BrandMark falls back to static. The birth choreography is **event-driven only**: Constellation dispatches `adam:core-birth`/`adam:core-docked` and `site-header.tsx` listens + hosts the `[data-brand-core]` anchor — renaming either side leaves the logo core invisible. ScrollyStory captions depend on the `.scrolly-cap.scrolly-on` rule in `app/globals.css`. The six newer tailwind keyframes are choreography-specific, not generic tokens: `core-arrive`/`core-beat`/`orbit-once` (BrandMark), `dial-sweep` (the /analysis idle decoration, purely decorative; Constellation `mode='ambient'` currently has no consumers), and `land-flash`/`reasoning-land` (the 420ms /analysis landing beat — see the vitality bullet).
- **Hero honesty invariant (`components/analysis/orbital-hero.tsx`):** no UI state precedes its real event. The core number is an **asymptotic estimate capped at 0.92** (`useAsymptoticProgress`, inline `1-exp(-t/26)`) while running — it only reaches the real `actionable_pct` when `resolved` (driven by `a4Status === 'done'`, a real stream event). **Satellites light only on `settled` states** (`done`/`anomaly`); an agent in `error` stays dark even after the core resolves. **A3 (Gráfico) orbits an isolated dashed ring (`R_ISO`, counter-rotating) with its own filament and no tether to A1/A2/debate; Estructura is an opt-in satellite on the solid inner ring (`R_INNER`, same as A1/A2), also without an A1/A2/debate tether.** The `final`/per-agent events come from the `/api/agents/run` **NDJSON** stream (not theatrical timers — the carousel was retired). Any refactor of the running/resolved states preserves all of this. (The retired neural-brain hero — `confluence-hero.tsx` + `analysis/neural/*` — was deleted 2026-06-29.) Fase-1 additions keep the doctrine: every rAF-driven `.style` write in the hero gates on `f.reduced` (the global reduced-motion CSS cannot reach JS writes — any new rAF visual needs its own gate); the resolve crescendo (520ms pop + glow bloom) is seeded with `lastResolved` at mount, so a hero that mounts already-resolved (persisted run after soft-nav) never re-fires it — only the real `scanning→resolved` edge does; and the action box reserves constant height (`min-h-[4rem]` + `line-clamp-3`) as a CLS fix — keep the reservation.

## What not to touch without owner approval

- A3 isolation (any of the three layers).
- **Estructura isolation** — its `CLAVES_PERMITIDAS` guard in `agents/estructura/compute.ts` + `narrate.ts` and the `.strict()` schema at `app/api/agents/estructura/route.ts` (a mirror of A3 isolation, with its own tests). Also don't break `resolveEstructuraSymbol` (futures map, e.g. `XAUUSD→GC=F`) or drop the `estructura_output` column in `analyses_log` during a schema change.
- The `MODELS` constant in `lib/anthropic.ts` and the corresponding model assignments in each agent's `narrate.ts` / `client.ts`. Costs and the Hobby latency budget assume this allocation (ADR-001).
- `lib/ratelimit.ts` lazy-init pattern — eager init has bitten this codebase before.
- `DEFAULT_TIMEOUT_MS = 25_000` without recalculating the worst-case lambda budget (see the in-file comment about the 30s revert).
- The literal `DISCLAIMER_LITERAL` string (separator is U+00B7).
- The generated `types/db/supabase.ts` — don't hand-edit it or reintroduce `as any` casts on Supabase calls; regenerate after migrations instead.
- `eslint` pinned to 8.x (peer of `eslint-config-next@14`) — bumping to 9 needs `eslint-config-next` to move too.
- **A3 live candle window:** `lib/market/snapshot.ts` fetches `fallbackDaily(ticker, '1y')` (~252) and caps with `slice(-300)` (≥205). A3's `computeTechnical` runs SMA200 (needs ≥200), golden/death cross (≥205) and `rango_52s` (≥200) over those candles; reverting to `'3mo'` or dropping the slice below 205 silently kills all three in prod — unit tests still pass because they feed candles straight to `computeTechnical`, bypassing the fetch+slice. `cmt/scan` and `estructura` already pass `'1y'`.
- The design token SSOT (`tailwind.config.ts` ↔ `app/globals.css :root` must match) and the semantic-color rule (`emerald/rose/amber` = market data only) — see **Design system invariants**.
- The `/signals → /watchlist` permanent 308 redirect in `next.config.mjs`, and the survival of `GET /api/signals` / `POST /api/signals/[id]/ack` / `POST /api/cmt/scan` — the page is gone (ADR-003 F5) but legacy deep-links (`?from=signal`, `login?next=/signals`) live only through the redirect, and the radar consumes those endpoints.
- `TradingHorizon` enum literals (`intradia`/`swing`/`posicional`): hardcoded in the `evaluate-trades` jsonb filter, in `HORIZON_WINDOW_DAYS` (swing 30d / posicional 120d — don't lower posicional's 120d: already-evaluated `trade_outcomes` assume it; that's why the label says "≈1 mes+" instead) and in persisted `a3_output`. Renaming breaks scoring silently. UI labels go through `horizonteLabel()` (`lib/analyses/horizon.ts`) — never print the raw enum.
- `trade_outcomes` composite PK `(analysis_id, source)` (migration 0018): never assume one row per `analysis_id` — a `.maybeSingle()` on it errors once an analysis has both sources evaluated.
- The bounded `.in('signal_id', …)` second query in `/api/watchlist/radar` (admin client over service-role-only `signal_trade_outcomes`, ids strictly from RLS-filtered RPC rows). Widening or unbounding it is a cross-user leak; locked by its route test.
